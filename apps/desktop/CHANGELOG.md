# @openfilm/desktop

## 0.1.6

### Patch Changes

- [#23](https://github.com/openfilm/openfilm/pull/23) [`e688860`](https://github.com/openfilm/openfilm/commit/e688860dec6717c4c67b5cf26b920f5b3d9ce416) Thanks [@PazChen](https://github.com/PazChen)! - Studio: the Desktop dialog is laid out again, with the app's window and the agents it works with beside eight clear points (two-way chat with the editor, live changes, media dropped in, any agent, faster preview and export, no terminal or dependencies, updates, kept chats) and the download. A layer selected on the picture lets go when the timeline is pressed or the playhead leaves its clip, and the picture no longer gets a ring of its own while something is selected. The bar over a selection shows at once, without rising. The subtitle row's menu can hide it, and says where it comes back. The export's "Save to" is one button with the folder's name; in the desktop app it opens the system's folder dialog instead of a typed path. A track's name shows under its badge, so the track heads keep their width. The examples follow the Projects view (cards or rows). A media folder just named stays in place until the listing has it, and a click on empty space in the media pane lets go of what is selected. The Desktop dialog's download sits bottom right beside the version, and its agents' names show on hover. Settings → Models shows a choice only while its provider is connected. Files dragged from the computer onto a media folder go into that folder. A page previewed in the media pane starts at 0 when another is picked. The projects' sort by name says so, a folder's name sits in the Projects title (its projects start where the list does), folders in the list view show their covers, and removing a project whose folder is gone says that nothing of it is left on disk. Projects folders can hold folders, with the trail to them in the title. The media pane can show a list as well as a grid, says why a web page cannot go into a folder, and no longer picks a file when a drag starts. The export's "Save to" opens the system's folder dialog in a browser too (Studio opens it on this computer), exports go to the Desktop by default, and the frame rate is picked from an editor's list (10 to 60 fps, 23.976, 29.97, 59.94, and 120). `pnpm dev` refuses to start a second time for the same checkout. Studio works inside another app's frame (an agent's preview pane): its sign-in has a partitioned twin a frame keeps, and the film's pages no longer refuse to be framed there. A clip dragged onto another clip of its own track goes in between them, as in an editor's main track, instead of cutting it (⌥ still overwrites). A transcript that runs past the end of its file (made from another version of it, such as one sped up in place) is listed to be made again, so its subtitles no longer drift and lose their end. A browser that opens Studio's address without its key is told so, and which address lets it in, instead of a page that seems to reconnect forever. The manual tells agents to change a clip's speed only with `speed`, so its subtitles stay with it. A media file opens playing from its start, with one full-screen button in its bar. Ratios add 3:4, 3:2, 2:3, 2.39:1, 1.85:1 and 2:1 and any ratio typed from 1:4 to 4:1. The project's frame rate is picked from the same list as the export's (23.976 to 60, 48 and 120), in Studio's own menu. Web pages can be moved into folders like any media: their links (and those of every page pointing at what moved) are written again; paths a page makes while it runs are named before the move. The viewer's ratio button and the inspector change the film's canvas itself, at any time, as CapCut does: the shapes CapCut offers (and Fit to the first picture, and any typed size), the canvas's short side kept, and the film scaled into it whole, centered, in one undoable step; the inspector gives the words that ask the agent to lay the film out again. A delivery frame (bars or a crop) is now the export's alone. The export dialog's destinations scroll, so its note is never cut. A web page that sets no size of its own keeps the size it was laid out at when the canvas changes shape (film.html's new `size` on a page clip, which Studio writes), so it is scaled into place like a video instead of being laid out again smaller.
